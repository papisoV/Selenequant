# Product

## Register

product

## Platform

web

## Users

Solo 量化研究者(产品作者本人 = 目标用户画像)。**"个人投资者"是市场定位,不是能力边界。**

用户是 **Director**:拥有研究方向权 —— 提出 / 追问 / 换解释 / 停掉一个方向 / 固化判断。**不是逐条指挥的操作员,也不只是终点按 approve 的审批人。**

每天打开 Selene 的第一件事:看"研究团队当前在理解什么、最近完成了哪些调查",读已完成的研究结论,在关键节点行使方向权。用户不需要知道"哪个页面里有哪个量化工具",只需要知道**我现在到底想弄明白什么**。

## Product Purpose

SeleneQuant 是**个人投资者的 AI 量化研究团队** —— 一个围绕持久问题持续研究、验证、决策与复访,并积累可追溯研究经验的 **AI Quant Research Organization**。

> 用词纪律:对外统一称「团队」,内部 Domain / Architecture / Spec 统一称「组织」。**不得互换,也不得各自长出定义。**

**核心单位是 Question,不是 Work:**

```text
Question → 需要继续了解 → Work Generation 产生研究动作     ← 研究组织
Work Generation → 产生 Work → 找个 Question 挂上去          ← 任务系统(禁止)
```

**与工具的分界:工具保存答案,更聪明的工具保存问题与历史;Selene 让上一段历史改变下一次判断。**

分界不在"有没有记忆"(现代工具都有项目上下文 / 文件 / 记忆),也不只在"保存的是不是结构化关系"—— **Obsidian + Git 连结构化关系也保存得了**。分界是:**这些历史会被系统自动取回,并因此改变下一次研究。** 只有保存、没有召回,就是 **Research Archive**(见 Differentiation)。

**能力可以宽,叙事必须窄。** 市场数据 / 回测 / 调参 / 风控 / 组合 / 执行 / 新闻 / 链上 / Agent / MCP 全部保留,但**都不是一级叙事** —— 砍的是对外叙事入口,不是技术能力。用户看到的不是"Selene 拥有 8 个模块",而是"我把这个问题交给 Selene,它正在查"。

**北极星:让下一次判断建立在上一次真实发生过的结果之上,并因此更有依据。**

**验收判据(可证伪)** —— **分两道,不得混为一谈:**

|  | 测什么 | 怎么测 | 不成立时 |
|---|---|---|---|
| **Gate(机制)** | 第二次回答是否**真的**利用了第一次留下的东西 | **两进程**:round1 写库退出;round2 只开库文件、**不 import 前一个的任何东西**。**再加对照组 round2B 禁用召回** —— 比较两次的 Hypothesis / Experiment / Decision 是否不同 | 召回根本没发生 → **实现没做完**,不证伪任何东西,**去修** |
| **Grade(价值)** | 这个"不同"对用户是否真有价值 | 30 天真实使用。访谈问题 =「**上一次研究的结果,有没有改变你这一次的研究?**」 | 用户答「我自己用 Obsidian + Git 就行」→ **定位被证伪** —— 只是更漂亮的档案柜 |

> **只有对照组的差异能归因给 Memory。** 没有对照组,"不同"可能来自新证据 / 新假设,与 Memory 无关。
> **只有 gate 过了才配谈 grade;gate 过了而 grade 不过,说明造的是更漂亮的档案馆。**

## Differentiation

差异化不是单个 feature,是**研究连续性**:同一个问题的历史研究、现实结果与经验会进入下一次判断,并因此改变它。

> **两句缺一不可。** 只留前半(保存了历史)= 档案柜,Obsidian 就能做;只留后半(能根据上次调整)= 一次性 agent 也能做到。区别落在「**自动取回**」这四个字 —— **不要求用户记得去翻。**

**真正的对手不是 QuantDinger,也不是 Claude —— 是用户用现有工具拼出来的「足够好的连续性」。**

用户随时可以回答:「那我自己用 Git + Obsidian + Claude + QuantDinger,不就有 continuity 了吗?」**这个回答是成立的**,所以任何对 Obsidian 也成立的句子都不是分界。

最危险的失败模式因此有了名字:**Research Archive** —— 存得很好、搜得很好、展示得很好,但历史不改行为。这一条已进验收判据(见上)。

| 护城河 | 一句话 |
|---|---|
| **Temporal / at-the-time intelligence** | 不宣传"AI 预测最准",宣传**我们知道当时到底发生了什么、当时为什么这么判断** —— 回答 at-the-time,不是 hindsight |
| **Strategy Memory** | Strategy 不只是 executable object,更是 **epistemic object**:「我们为什么相信这条策略?」 |
| **Outcome → Memory** | 不只是拥有 Memory,而是 **Memory 会改变行为**。真正的组织记忆 = 能够改变以后决策的历史经验 |

> 前两条的机制在 Domain Spec:Episode 不可改 / 观察只增(同一事件可挂多条不同时点的 Evidence),所以"当时 vs 现在"是数据模型保证的,不靠纪律。

**物种测试** —— 四个产品并排,读完应该明显不是同一种东西:

```text
Trading / Quant Software    我提供工具,你操作。
AI Financial Chatbot        你提问,我回答。
AI Quant Agent              你给任务,我执行。
Selene                      你给问题,我持续研究;现实给结果,我把结果带回下一次判断。
```

**不以类别定义当差异化定位**:"AI Quant Research Organization" 适合当**类别定义**(它今天已不稀奇);锋利的是后半句 —— **一次研究不会结束,它会改变下一次研究。**

**不打正面战**:QuantDinger 是 **AI Quant Operating System**(把量化全流程都装进去),Selene 是 **AI Quant Research Organization**(只做研究组织的记忆与判断连续性)。物种不同,不拼模块数量。

## Brand Personality

克制、专业、可信赖的研究团队——不是聊天机器人。三词:严谨(Rigorous)、冷静(Composed)、负责(Accountable)。情感目标:用户信任系统给出的结论,到愿意按一个键批准它继续。视觉语言 = 金融终端(深色、密度、tnum 数字),研究组织的多角色/多步骤轻量可感知但不喧哗。

## Anti-references

- 聊天气泡式 AI 界面(结论埋在对话流里,不可回源)
- **Tool Workspace** —— 把 245 个工具换成"一张台面 + 挂工具":视觉整合了,**产品本质没变**(仍是同一物种)
- **Agent Task Manager / Jira** —— 把"当前这件工作"当中心;正确的问题是"我现在正在**理解**什么",不是"现在正在**干**什么"
- **AI Terminal(作为产品身份)** —— 不要把 Terminal 当成 Selene 的产品身份;Terminal 可以是 Selene 的一等研究界面(与 GUI/Agent 同一 Runtime 之上的平行操作面,一级词汇 = Director/Research 动词,不是 Tool 动词)。施工无限期搁置,待有明确思路再启(2026-09-19 拍板)
- SaaS 营销卡片栅格(图标+标题+正文重复卡片)
- 空泛待办列表(给用户 18 个任务,而不是 1 个已完成调查)
- 装饰性动效 / 玻璃拟态 / 渐变文字 / hero-metric 模板

## Design Principles

1. **结论先行** — 用户先看到推荐和决策动作,再下钻到证据;不让用户读完过程才能到达结论。
2. **证据可回源** — 每个 claim 点得回原始数据(回测/行情/事件);没有证据支撑的陈述降级展示。
3. **三键拍板** — 任何决策点动作不超过 3 个(批准继续 / 换个方向 / 暂时忽略);批准是显式动作,不是默认。Question 面(2026-09-19 追认):动作 = 3 拍板键(查清楚了/换个问法/先放一放)+ 1 继续查 —— 继续查不是拍板键,是把问题留在进行时的动作,不占三键名额。
4. **组织感但轻量** — 研究团队的多角色/多步骤可见,但不做成 agent 聊天剧场;每步的存在感 = 它的结论价值。
5. **终端一致性** — 融入现有深色金融终端设计系统(11px 基准、tnum、蓝 accent),不另造视觉语言。

## Accessibility & Inclusion

WCAG AA(正文 ≥4.5:1)。深色主题下 muted 文本对比度是历史风险点:正文用 ink/ink-2,不用 ink-3 以下。数字一律 tabular-nums。涨跌语义色必须用现有 pos/neg utility(zh-CN 会翻转红涨绿跌),不许硬编码绿涨红跌。
